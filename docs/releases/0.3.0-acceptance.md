# CyberAudio 0.3.0 发布与验收（2026-11-06）

源码已合入并推送 main，发布提交为 `3fe2562bf9f71bfe26a9f68456a75984be639535`，版本为 **0.3.0（6）**。[Release](https://github.com/Arasaka-Academy/CyberAudio/releases/tag/v0.3.0) 与 [发布工作流](https://github.com/Arasaka-Academy/CyberAudio/actions/runs/42060497276) 已完成，构建、资产上传后重新下载核对、Pages 更新清单部署全部成功。

## 安装与回滚

M4 原安装为 0.1.0（3），早于 Sparkle 支持版本，因此本次为受控手动替换。安装使用解包后的原始正式 App，保持 `local.cyberaudio.mac`，不修改发布包的 bundle ID 或签名。

先保存旧 App、完整配置目录及已有偏好文件，再验证固定模型，等待正式服务连续 3 次空闲后退出旧 App／Python Helper，确认进程退出和端口释放。严格验签通过的新 App 随后进入 `/Applications/CyberAudio.app`。新 App 直接拥有一个 `CyberAudioService` 子进程，`backend=mlx-swift`、`device=metal`，Helper 哈希与正式包一致。

配置目录的 4 个文件逐字节保持，包括 API Token、模型路径、8765 端口与原 HTTPS URL。23 个固定模型文件验证通过；只在原模型目录新增缺失的两个派生 `tokenizer.json`，没有替换已有权重。旧 Python runtime 留在原数据目录。

旧 App 与配置备份在目标机：

```text
~/Library/Application Support/CyberAudio/Backups/0.1.0-to-0.3.0-20261105T163749Z/
  CyberAudio.app                 # 安装前的 App 副本
  previous-installation.app      # 退出后移入的原安装
  config/                       # 含私有 Token，不上传仓库
  preferences.plist             # 已有偏好文件
```

正式 8765 服务通过认证拒绝、模型身份、9 音色列表、中英文真实录音识别、中文／英文 WAV 生成、完整 PCM、断连取消后恢复、更新暂停新任务与取消恢复。随后取得原生更新租约并排空，实际停止 App／Helper、重新启动；旧 Helper 消失，新实例 ready，配置字节和 Helper 哈希仍一致，重启约 7.83 秒。

另一台 M1 Max Mac 以正常证书／主机名验证连接原地址 `https://mac-mini.civet-beta.ts.net:8443`，取得 ready、认证模型列表，并完成真实 TTS 和请求状态查询；输出 180,524 B 的 24kHz／单声道／PCM16 WAV，HTTP 总耗时约 2.76 秒，状态 completed。该私有 HTTPS 请求显式绕过代理；Token 只在验收进程内存中使用，未写入验收证据。

原始证据：[安装记录](../evidence/release-0.3.0-2026-11-06/deployment.json)、[正式接口冒烟](../evidence/release-0.3.0-2026-11-06/production-smoke.json)、[受控重启](../evidence/release-0.3.0-2026-11-06/production-restart.json)、[外部 HTTPS](../evidence/release-0.3.0-2026-11-06/external-https.json)。

需要回退时，先保存工作并退出当前 App，确认其 Helper 与端口已经停止；把当前 App 移到另一备份位置，再从上述 `previous-installation.app` 复制回 `/Applications/CyberAudio.app`。原模型与旧 runtime 均保留，配置默认无需恢复；备份中的私有配置仅在确认配置损坏时使用。本次保留了回滚资产，未实际降级正式服务。

## 验收边界

原生更新测试夹具使用独立 bundle ID、隔离数据和 `CyberAudioFixture`。真实 Sparkle 已请求本地签名清单和 ZIP，但本机桌面无法解析该窗口的 AX，截图也失败；未执行前台接管，安装后仍是 build 4。因此本轮未确认原生 Sparkle 界面的实际安装／重启。它与服务的更新准入、租约、排空自动化结果分开记录。

App 使用 ad-hoc 签名，未做 Developer ID 公证。真人试听、真实麦克风与播放、登录项和重新登录、长文本及中英混说／数字专名专项、功耗与 Instruments 计算单元分析仍需单独验收；自动生成音频和公开录音评分不替代这些项目。
