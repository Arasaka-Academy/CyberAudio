## 验证结果

本地完整 `make check`、版本递增检查、App 构建及严格嵌套签名检查通过。远端完整回归、正式包构建与资产上传、Pages 更新源部署全部成功。

六个正式资产已通过 GitHub Release asset API 下载，长度、SHA-256 与发布清单一致。公开 Pages 清单与已签名的发布清单逐字节一致，版本为 0.4.3、build 为 10。清单及 ZIP 的 Sparkle EdDSA 签名验证通过。没有将 asset API 下载视为普通浏览器或应用内下载路径的验收。

ZIP 与只读挂载的 DMG 均通过严格嵌套验签。两个包的 Info.plist、三个可执行文件及五个图标资源一致，架构为 arm64，无 Python 运行时。应用仍使用 ad-hoc 代码签名，不构成 Developer ID 公证验收。

两个正式包中的 `CyberAudio.icns`、`MenuBarIdle.png`、`MenuBarIdle@2x.png`、`MenuBarActive.png`、`MenuBarActive@2x.png` 均与设计源文件逐字节一致。AppKit 成功读取 ICNS 的 10 个尺寸表示，以及两个菜单栏图标各自的 18／36 像素表示；菜单栏逻辑尺寸均为 18 × 18 pt，素材为黑色图形加透明通道。应用配置的 `CFBundleIconFile` 指向新 ICNS。

两机各自的四个配置文件逐字节保持，包括 Token；已有模型、旧 runtime 均保留。本机听写偏好保持 Control＋Shift＋K。每台机器仅运行一个正式 App 和一个由它直接拥有的原生 Helper，旧 App／Helper 已退出。

每机完成中文、英文各一次合成语料识别和 WAV 合成，四项语音请求均返回 200；两次合成输出均为 24 kHz／单声道／PCM16。未认证请求返回 401；更新准备期间拒绝新推理，取消更新后恢复 ready。另从本机以正常证书及主机名校验调用 Mac mini 原有 `https://mac-mini.civet-beta.ts.net:8443`，模型列表和中文 TTS 成功，生成 169,004 B WAV，请求状态为 completed。

## 听写与界面边界

初次安装时本机处于锁屏状态，辅助功能和输入监控的允许记录仍绑定旧版签名。解锁后已通过正常系统设置和正式 App 的权限请求恢复授权，用户在系统窗口完成了认证。只读检查确认两项系统权限均允许当前 0.4.3 的代码要求；麦克风也在 App 内显示已开启。没有直接修改 TCC 数据库或重新签名发布 App。

本机听写设置已显示三项权限开启，以及仅在监听启动后显示的“按住 ⌃⇧K 录音，松开后在原输入框输出”。用户按住 Control＋Shift＋K 约两秒再松开，无需说话，已明确确认听写 widget 出现。配置、Token 和快捷键保持一致，正式程序及图标仍匹配发布包。权限恢复后的新服务实例再次通过中英文各两项识别／合成、鉴权和更新暂停／恢复检查，最终 ready、空闲、无更新租约。[本机权限与实体按键验收](../evidence/release-0.4.3-2026-11-06/local-permission-refresh.json)、[实际设置截图](../evidence/release-0.4.3-2026-11-06/local-dictation-permissions.png)、[恢复后服务回归](../evidence/release-0.4.3-2026-11-06/local-permission-refresh-service.json)。

Mac mini 未验证听写界面、麦克风或实体按键，安装检查时系统数据库中没有该 App 的辅助功能／输入监控条目。本机新的菜单栏实景、真实语音听写和跨应用输入仍需单独验收；合成语料接口测试及 widget 出现不替代这些项目。[权限与界面状态](../evidence/release-0.4.3-2026-11-06/dictation-installation-status.json) 保留了初次安装时的边界及后续恢复结果。
