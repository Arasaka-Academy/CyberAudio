## 修复与回归

在真实 AppKit 事件分发测试中，快捷键视图失去第一响应者后，旧实现无法录入组合键。录入现在使用限定于当前弹窗的本地事件监听，关闭弹窗时清理，并更新 SwiftUI 回调。测试同时覆盖系统保留快捷键、Escape、右 Option 和其他窗口的事件隔离。

旧 HID 轮询会在从未观察到硬件按下时提前取消有效的会话按键；100 ms 轮询早于 150 ms 录音阈值。现在同时读取会话与 HID 状态，仅在本次按下曾被轮询观察到后，才用轮询恢复丢失的松键。行为测试覆盖会话按键无 HID 状态与松键只提交一次。

按下立即显示“准备听写”浮层，满 150 ms 才开始录音。真实控制器与 NSPanel 测试验证立即可见、保持输入焦点、短按关闭及迟到任务清理。引擎未就绪或其他音频正在处理中时显示原因。

这些测试已复现并修复实现缺陷；不据此认定已排除用户物理键盘路径的所有问题。

## 自动检查与发布

正式发布的六个文件均已在本机下载并核对长度、SHA-256。下载通过 GitHub Release asset API，资产 CDN 使用可达地址；本机未据此声称普通浏览器下载路线通过。Pages 更新源与 Release 中的 appcast 字节一致，版本为 0.4.2、build 为 9。更新源及 ZIP 的 EdDSA 签名验证通过。

ZIP 和只读挂载的 DMG 均通过严格嵌套验签，三个可执行文件的哈希一致，架构为 arm64，无 Python 运行时。应用仍采用 ad-hoc 签名，不构成 Developer ID 公证验收。

## 正式包安装与模型测试

机器为 Apple M1 Max、32 GB、macOS 27.0.1。安装前确认旧实例就绪、空闲、无更新租约，通过应用支持的 SIGTERM 正常退出，保留旧 App 后安装已验证的正式 ZIP。安装后三个可执行文件与正式包逐字节一致，现有配置及 Token 与原备份逐字节一致。证据不含凭证。

正式安装后的默认 8765 服务仅有一个 App 和一个归属该 App 的原生 helper，完成真实 Qwen 模型的以下自动测试：

| 项目 | 结果 |
| --- | --- |
| 中文识别，7.1 秒固定合成语音 | 成功返回中文与数字；本次 HTTP 约 784 ms |
| 英文识别，5.45 秒固定合成语音 | 成功返回英文与数字；本次 HTTP 约 576 ms |
| 中文与英文语音合成，各一次 | 均返回有效 24 kHz、单声道 PCM16 WAV，分别为 3.92 秒与 4.00 秒 |
| 未授权模型请求 | 返回 401 |
| 更新 prepare／拒绝新推理／cancel | 通过，暂停期间返回 503，取消后恢复 |

## 桌面验收边界

本地 0.4.1 候选包已通过桌面快捷键录入：裸 Tab 被收到并提示无效组合，随后接收 `⌃⌥⇧K`、关闭弹窗并保存，最终恢复右 Option 并从界面读回。真实失焦情形由进程内 AppKit 回归验证；不将裸 Tab 录入当作焦点导航测试。

用户曾要求“稍后验收，先完成自动测试”。最初 0.4.2 安装后的锁屏阶段，Cua 可观察主窗口截图，但无法读取窗口辅助功能树，当时未完成正式包的权限和实体按键验收。以下补充记录保留该边界，并说明后续解锁后的实际结果。

### 解锁后的补充验证

用户解锁后，继续验证同一个正式 0.4.2（9）安装包，并核对主程序仍与已发布 ZIP 的哈希一致。正式包的“修改…”弹窗已实际接收裸 Tab 并提示无效组合，随后保存 `⌃⌥⇧K`、关闭弹窗；恢复默认后从设置页读回右 Option。这补足了正式包的快捷键录入界面验收。

正式包最初将三项权限都显示为未开启。系统设置中的麦克风开关虽为开启，应用仍报告未授权；通过正常系统界面关闭、重新开启并按系统提示重启后，正式包已读回“麦克风已开启”，模型服务也恢复 ready、idle、无更新租约。

辅助功能页面名为“设备控制和数据访问”。用户完成系统认证后，发现辅助功能和输入监控的开关即使开启，App 仍读不到授权。仅对 CyberAudio 的系统 TCC 记录作只读查询，确认这两项记录仍绑定 0.4.0 的 ad-hoc CDHash；单纯关闭、开启开关没有更新旧代码要求。

通过正常系统设置界面，仅移除并重新添加 CyberAudio 当前正式包后，两项代码要求均更新为 0.4.2 的 CDHash，授权值为允许，当前 App 通过对应要求的严格签名验证。没有修改 TCC 数据库，也没有重新签名或替换已安装的 App。随后设置页从 App 内读回麦克风、辅助功能、输入监控全部“已开启”，“启用快捷听写”为开启，监听状态就绪。详见 `permission-refresh.json`。

### 外接键盘与实体快捷键

用户再次按右 Option 后反馈仍无浮层。在有界的只读修饰键诊断中，HID 与会话层均收到左 Option（代码 58），但没有观察到右 Option（代码 61）；仅按右侧按键的后续诊断也未观察到修饰键事件。用户确认使用外接键盘。此证据没有确定右侧按键缺失的具体映射或硬件原因，右 Option 在这把键盘上的验收仍未通过。

通过正式包的“修改…”弹窗保存 **Control＋Shift＋K（⌃⇧K）** 后，用户用实体键盘操作并确认“出现了”听写 widget。Cua 同时观察到 App 进入“正在本机识别语音…”，随后恢复“开始录音”的空闲状态。该次要求无需说话，界面报告音频 0.1 秒、处理 0.38 秒；这补足了实体组合键唤出浮层和录音后处理的证据，不构成持续三秒录音或真人语音识别准确率验收。浮层出现由用户确认，没有捕获到浮层截图。

本机当前保留已确认可用的 **⌃⇧K**。默认配置仍为右 Option，可在设置页继续修改。修饰键诊断均已结束，未记录文字。最终设置截图见 [dictation-shortcut-ready.png](../evidence/release-0.4.2-2026-11-06/dictation-shortcut-ready.png)，补充结构化记录见 `gui-unlocked-check.json`。

实体按键测试后再次确认：正式包三个可执行文件的哈希仍与 Release 一致，配置及 Token 仍与原备份逐字节一致，仅有一个 App 和归属它的原生 helper，STT／TTS 均 ready、busy=false、updating=false。详见 `post-permission-service.json`。

真人说话后的识别文本、跨应用仅插入一次、切换输入位置后保留结果仍待后续验收，现有自动与实体快捷键结果不替代这些项目。

运行时继续使用 Swift＋MLX Swift／Metal，没有迁移 Core ML／ANE。
