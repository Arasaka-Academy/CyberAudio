## 修复与回归

在真实 AppKit 事件分发测试中，快捷键视图失去第一响应者后，旧实现无法录入组合键。录入现在使用限定于当前弹窗的本地事件监听，关闭弹窗时清理，并更新 SwiftUI 回调。测试同时覆盖系统保留快捷键、Escape、右 Option 和其他窗口的事件隔离。

旧 HID 轮询会在从未观察到硬件按下时提前取消有效的会话按键；100 ms 轮询早于 150 ms 录音阈值。现在同时读取会话与 HID 状态，仅在本次按下曾被轮询观察到后，才用轮询恢复丢失的松键。行为测试覆盖会话按键无 HID 状态与松键只提交一次。

按下立即显示“准备听写”浮层，满 150 ms 才开始录音。真实控制器与 NSPanel 测试验证立即可见、保持输入焦点、短按关闭及迟到任务清理。引擎未就绪或其他音频正在处理中时显示原因。

这些测试已复现并修复实现缺陷；不据此认定已排除用户物理键盘路径的所有问题。

## 正式包安装与模型测试

机器为 Apple M1 Max、32 GB、macOS 27.0.1。安装前确认旧实例就绪、空闲、无更新租约，通过应用支持的 SIGTERM 正常退出，保留旧 App 后安装已验证的正式 ZIP。安装后三个可执行文件与正式包逐字节一致，现有配置及 Token 与原备份逐字节一致。证据不含凭证。

正式安装后的默认 8765 服务仅有一个 App 和一个归属该 App 的原生 helper，完成真实 Qwen 模型的以下自动测试：

| 项目 | 结果 |
| --- | --- |
| 中文识别，7.1 秒固定合成语音 | 成功返回中文与数字；本次 HTTP 约 784 ms |
| 英文识别，5.45 秒固定合成语音 | 成功返回英文与数字；本次 HTTP 约 576 ms |
| 中文与英文语音合成，各一次 | 均返回有效 24 kHz、单声道 PCM16 WAV，分别为 3.92 秒与 4.00 秒 |

## 桌面验收边界

本地 0.4.1 候选包已通过桌面快捷键录入：裸 Tab 被收到并提示无效组合，随后接收 `⌃⌥⇧K`、关闭弹窗并保存，最终恢复右 Option 并从界面读回。真实失焦情形由进程内 AppKit 回归验证；不将裸 Tab 录入当作焦点导航测试。

用户已在系统窗口确认授权，也明确要求“稍后验收，先完成自动测试”。最终 0.4.2 安装后，系统实际回报屏幕再次锁定，Cua 可观察主窗口截图，但无法读取窗口辅助功能树。因此本轮未完成最终包的三项权限与全局监听状态读回，也未完成物理按住右 Option、真实麦克风录音及跨应用自动插入验收。用户之前的授权确认不等于新安装包的权限状态已得到验证。

后续解锁后，应确认设置页显示监听就绪，实际按住右 Option 出现浮层，松开后仅在原输入框插入一次结果。用户切换输入位置时，应保留识别结果供复制。现有自动测试不替代这些物理验收。

### 解锁后的补充验证

用户解锁后，继续验证同一个正式 0.4.2（9）安装包，并核对主程序仍与已发布 ZIP 的哈希一致。正式包的“修改…”弹窗已实际接收裸 Tab 并提示无效组合，随后保存 `⌃⌥⇧K`、关闭弹窗；恢复默认后从设置页读回右 Option。这补足了正式包的快捷键录入界面验收。

正式包最初将三项权限都显示为未开启。系统设置中的麦克风开关虽为开启，应用仍报告未授权；通过正常系统界面关闭、重新开启并按系统提示重启后，正式包已读回“麦克风已开启”，模型服务也恢复 ready、idle、无更新租约。

辅助功能页面名为“设备控制和数据访问”，其中 CyberAudio 开关实际为关闭。开启时 macOS 弹出新的“隐私与安全”管理员确认，要求输入密码并点击“修改设置”。当前等待用户在该系统窗口完成认证，未把开关的暂时显示当作授权成功。输入监控刷新、全局监听状态、物理长按、浮层及跨应用听写验收仍待该确认完成后继续。补充记录见 `gui-unlocked-check.json`。

运行时继续使用 Swift＋MLX Swift／Metal，没有迁移 Core ML／ANE。
