# 文本输入布局的独立对照

本阶段用当前 R11 SDK 的私有副本，对比现有完整文本预填充与官方 `non_streaming_mode=False` 的逐步文本输入。两者均由保留的 [Qwen 源快照](../retry-and-matrix/reference-source-provenance.json)定义；现有布局与官方非流式分支一致，没有把布局差异认定为代码缺陷。参考快照 SHA 为 `25c42656bcf810f06ef6bc1839bd7083f3c8cfedac3a147c4060b4262b1c96a0`。本轮只读查询 SDK 上游同文件提交，最新仍为已包含的 `1e9c8eee190739dee7e8985920e8acced2197f22`，没有发现可直接采用的更新修复。

## 固定配对与结果

[预定计划](plan.json)在推理前固定五个条件、两种布局，共十次生成。主／辅助采样温度均为 0.7，top-k 50、top-p 1、重复惩罚 1.05、1200 token 上限保持原值。仅改变文本输入方式，[私有补丁](private-sdk.patch)没有写回正式 SDK 或共享对象。私有编译约 138.13 秒，十次生成约 73.57 秒，实际 ASR 回读约 19.18 秒，均正常结束。

| 条件 | 原完整预填充 | 私有逐步文本输入 |
|---|---|---|
| 已知失败，ono_anna／196 | 1200 token、96 秒、无 EOS；token／PCM 与原失败逐字节相同 | 6.08 秒、有 EOS；自动回读为完整原文 |
| 正常控制，ono_anna／31 | 2.56 秒；回读“持续验证语音服务的稳定性和恢复能力。” | 3.12 秒；回读“求验证语音服务的稳定性和恢复能力。” |
| eric 英文数字／31 | 6.88 秒，自动回读被检测为 Hindi | 6.8 秒，自动回读为“Tuan Fab.”，未确认正确数字 |
| dylan 英文数字／31 | 1.36 秒，自动回读为中文 | 1.52 秒，自动回读仍为中文 |
| ryan 日期与人名／31 | 回读保留完整原文 | 回读保留完整原文 |

全部十个输出都保留在[生成记录](generations.json)。原 96 秒失败音频分为四段，其余各一段，均经相同最终签名 App 的实际 ASR 自动检测；四个数字输出另做强制英文诊断，共 [17 次请求](asr.json)。两个原布局的英文数字 token／PCM 与 R11 已验收构建对照一致。强制英文返回的语言标签不证明实际发音语言，ASR 也可能自行误识别；本阶段没有人耳验收，不能单凭回读认定语音必然漏词、发错或改善。

已知失败能结束，同时出现正常控制的回读回退，英文数字仍未接受。因此不采用该候选，不继续为它重跑完整矩阵或严格两小时测试；原失败门槛保留，不能以小样本的结束数量替代稳定性或内容质量。
