## 单变量和小样本

原失败流的 1200 个主 codec ID 中，一个 ID 占约 81.6%，最长连续重复 119 次。它只说明码值分布，不能直接证明人耳听到重复，也不证明模型内部注意力或错误的唯一原因。

[协议](protocol.json)在加载模型前冻结：仅当主码采样历史的末八个 ID 相同且不是 EOS 时，把该 ID 的下一次 logit 置为负无穷；EOS、辅助码本、随机调用次数、完整文本预填充、重复历史、解码和长度上限不变。主／辅助温度仍为 0.7、top-k 50、top-p 1、重复惩罚 1.05，最多 1200 token。改动只存在于独立编译对象，[插入片段](insertion.json)和[构建程序](build.py)可审阅。

先重跑六个原样基线，全部完整 token／PCM 与保留参考一致，才运行候选。两个种子 196 的失败重复均从 1200 token／96 秒／无 EOS 变为 **113 token／8.96 秒／真实 EOS**，两次完整输出一致；原前 47 个 token 和前 44 帧音频相同。四个正常控制的完整 token／PCM 均保持原字节。

十二份完整输出分段后完成 36 次实际 HTTP ASR，分别使用自动语言与原生产语言，共 24 个合并路由。两个失败重复在两个路由均准确回读“持续验证语音服务的稳定性和恢复能力。”；全部八个正常控制路由保留基线内容。英文数字控制仅保持原结果，没有因此获得正确英文或人耳验收。见[小样本汇总](pilot-summary.json)、[逐次回读](pilot-asr-results.json)和[文件复核程序](analyze.py)。

小样本只取得完整队列的验证资格。第一次重新执行复核程序时，全部断言通过后因已有汇总文件而被排他写入拒绝；保留原文件，随后仅重新执行验证段并与原汇总逐字段比较，没有重跑生成或 ASR，见[复核记录](pilot-verification-refresh.json)。
