# 官方 codec 嵌入求和与单变量质量对照

2026-11-07，从 `main@b6a7de5` 继续原 TTS 质量调查。定位到可重复的求和精度差异；显式 FP32 累加的私有候选通过七例结束／时长条件，但内容条件失败，**未采用、未扩大到 144 例、未重启原 7200 秒 M4 负载**。原十五项审查修复计数不变。

## 源码与算子证据

官方 [QwenLM/Qwen3-TTS 固定提交](https://github.com/QwenLM/Qwen3-TTS/blob/022e286b98fbec7e1e916cb940cdf532cd9f488e/qwen_tts/core/models/modeling_qwen3_tts.py) 将 16 组 codec 嵌入拼接后一次 `sum`，再加文本嵌入；当前 Swift 和未修改 MLX Python 都逐次相加。官方 modeling 文件 SHA 为 `25c42656bcf810f06ef6bc1839bd7083f3c8cfedac3a147c4060b4262b1c96a0`，与旧留存快照相同，不能当作上游新修复。

原 8-bit 模型中这 16 张嵌入表实际为未量化 BF16；整份权重 SHA 为 `b696f4bf45f54497b6de758981e76f1410bd68af05a657477dee466b0202df1a`。审计只读取所需行，没有加载或运行完整 PyTorch 模型。

按执行前冻结的 [operator-protocol.json](operator-protocol.json)，使用旧采样顺序候选留存的全部六条完整轨迹：367 步／5,872 个 codec 值，包含一个失败轨迹的重复。逐份验证原报告、模型、prepared、步骤快照和 PCM 摘要；逐次 BF16 加法精确重建全部 367 个原生 next-input。独立 NumPy float64 累加及显式 BF16 ties-to-even 舍入同时验证 PyTorch CPU 的真实 BF16 求和及原生左折叠结果。

367 个 next-input 全部与 PyTorch 单次求和不同，其中 361 个实际用于下一步反馈，另外六个属于 EOS 后未使用的输入。实际反馈的 739,328 个元素中 453,893 个不同，最大绝对差 `0.00390625`，相对 L2 差平均约 0.50%。这些是固定历史轨迹的数值描述，包含重复样本，不能解释为总体失败率。

随后在同一组全部输入上验证真实 MLX 算子；Swift 探针链接 App 实际使用的共享对象，使用其 Metal 库，没有用 Python 包版本推断 Swift 行为。

| 实际运行库／设备 | 逐次 BF16 与原生一致 | 直接 BF16 sum 与 PyTorch 一致 | FP32 sum 后转 BF16 与 PyTorch 一致 |
|---|---:|---:|---:|
| MLX Python CPU | 367／367 | 367／367 | 367／367 |
| MLX Python GPU | 367／367 | 0／367 | 367／367 |
| MLX Swift CPU | 367／367 | 367／367 | 367／367 |
| MLX Swift GPU | 367／367 | 0／367 | 367／367 |

因此仅改写成 BF16 `sum` 不能在 GPU 建立本次算子一致。对照支持测试显式 FP32 累加，但尚未证明完整官方模型计算一致或语音质量改善。先前 Swift／MLX Python 的零误差比较也不覆盖这项双方共有的官方实现差异。

环境为独立私有 Python 3.13.18／PyTorch 2.15.0／NumPy 2.5.4；现有 MLX Python 环境为 MLX 0.32.4／NumPy 2.3.4。依赖锁及摘要已归档；没有改变项目 Python 要求或既有运行环境。

私有源文件只有 [source-delta.json](source-delta.json) 这一处变化：将 16 个 codec 嵌入的 BF16 左折叠替换为拼接、FP32 求和、转回原 BF16，再按原逻辑加入文本。独立检查反向替换后与正式 SDK 原文逐字节一致；两组使用同一个 caller，没有修改共享 SDK、对象或正式 App。

## 完整内容回读与拒绝原因

全部 14 份完整输出按确定规则切为至多 24 秒的片段，分别用 auto 和原生成语言识别，共 46 次请求、28 个合并路由、14 对比较。没有遗漏、重试或截短输出。沿用原作者混合分词评分，并用另一份编辑距离实现独立复算全部结果。

seed 117 两路都回读为“可以去验证语音服务的稳定性和恢复能力。”，与预定“持续验证语音服务的稳定性和恢复能力。”仍有三个编辑。dylan 两路的编辑数都增加；eric 数字也没有准确回读。原协议要求逐对不回退及已知问题准确回读，内容条件失败，候选被拒绝。

编辑数混合了 TTS 与 ASR 误差，没有数字语义等价处理或人耳听辨；它不能直接证明实际发音的错误类别。本次按事先固定的条件保留失败，没有放宽评分或根据自然结束作出质量通过结论。
