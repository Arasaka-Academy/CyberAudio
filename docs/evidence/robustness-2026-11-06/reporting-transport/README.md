# 验收失败报告的传输路径补全

本阶段继续修复 R9。`3d59609` 保存了正常读取响应后查询到的失败请求，但 WAV 错误响应或 PCM 连接中断会先抛出异常，尚未到查询步骤；仍可能丢失模型终态。

`83f0ec3` 在主负载、断流恢复和更新请求中记录响应状态、接收字节数、错误 JSON、请求标识以及传输错误。验收失败后，若尚未保存请求记录，额外执行一次有截止时间的终态查询；查询本身失败时单独记录，保留最初的验收错误。成功、失败、传输中断和未获得响应分别保留实际证据，没有将错误响应接受为成功。

[checks.json](checks.json) 记录两条新增真实 HTTP 回归：服务返回 422 JSON，以及发送有效 PCM 后在声明长度前断开连接。两条回归在修复前均因缺少 `failed_request` 失败；修复后目标文件 **10 项通过**，现役工具检查 **39 项通过、0 跳过**。测试编译实际 Swift 驱动并访问本地 HTTP 服务器，不启动 App 或模型。

App、Helper、模型参数和严格验收标准均未改变；当前 M4 两小时重测仍使用 `3d59609` 的诊断驱动，没有重启正在运行的任务。本工具修复不能证明先前 M4 失败已解决，也不构成新模型或两小时通过证据。`extended-validation` 中的 37 项回执对应此前阶段，保留原值。
