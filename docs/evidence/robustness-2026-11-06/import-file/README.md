# 音频导入的文件读取边界（R14）

续审日期：2026-11-07。基线为 `main@1425c57`，接续原会话已留下的失败回归。原导入按路径检查 `fileSizeKey`，随后调用 `Data(contentsOf:)`；符号链接的长度与它所指文件的实际长度不一致。20MiB + 1 字节的文件经链接报告为 13 字节，实际却完整读取 20,971,521 字节。生产 `AudioWorkspace.transcribe` 因而越过本地限制，直到服务准入才失败，见[元数据对照](symlink-size-probe.json)与[恢复后的红测](red.json)。此前 FIFO 阻塞假设被 Foundation 的即时拒绝排除，未将其当作已发生的界面挂起。

## 修复及验证范围

校验与读取现在使用同一个已打开的文件描述符：保留正常符号链接，拒绝非普通文件，先检查实际文件长度，再分块读取，累计最多 20MiB + 1 字节以检测读取期间的增长。使用非阻塞方式打开，避免等待 FIFO 写入方；句柄在成功、失败和取消路径均关闭。读取在独立任务执行，取消向该任务传递；主 actor 继续持有转写／更新等待，直到读取结束，随后才可能构建服务请求。

正式回归通过实际 `transcribe` 入口验证直接／链接超限文件、0 字节及恰好 20MiB、正常链接、目录与直接／链接 FIFO。失败保持原转写及会话 ID，并释放忙碌状态。[绿测](green.json)使用项目的 Swift 5 并发模式，加 `-warnings-as-errors`；原红测先确认了缺失的本地校验，未将编译或环境错误当作行为失败。

完整 `make check` 在 143.48 秒后 exit 0：36 项原生契约、44 项工具、14 组渲染，以及全部行为／正式编译检查通过。随后将原生 HTTP 导入改为 144,044 字节的三秒 WAV，直接路径和正常链接均返回完整三秒解码结果，防止只上传首个读取块；修改后的整个音频工作流再次 exit 0，119.60 秒包含 101.38 秒测试夹具重建。生产源码自完整检查后未再修改，新增音频工作流断言单独验证。

完整检查、额外 HTTP 内容完整性回归及顺序复查结果见[检查回执](checks.json)和[审查记录](review.json)。测试使用真实文件系统、原生 HTTP 与测试推理引擎；不据此声称模型、物理麦克风或人耳验收通过。
