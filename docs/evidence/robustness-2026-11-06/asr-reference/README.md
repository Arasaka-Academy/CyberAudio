## 公共边界捕获与单变量控制

原生调用现有公开 `preprocessAudio`、`buildPrompt`、`getAudioFeatures`；只增加独立 Swift 调用方，没有重编译或修改 SDK。捕获前的原生 `generateManaged` 文本全部复现 HTTP。Python 的原始生成也全部复现，然后独立捕获相同边界。

十二组原始音频 float32、音频 mask、prompt **值**全部一致；prompt dtype 可分别为 Int32／Int64，不声称 dtype 全部相同。Mel 和 encoded 的形状一致、数值有差异。60 项边界比较中 36 项逐值一致；最大 Mel 绝对差 `0.00012862682342529297`，最大 encoded 绝对差 `7.275491952896118e-06`。24 个快照合计 **110,186,840 字节**，保留于私有诊断目录。

每个输入均执行三个控制，共 36 次，方法替换在每个控制结束后恢复：

| 控制 | 保持／替换 | 与原生文本一致 |
|---|---|---|
| unmodified-repeat | 原始 Python 全路径 | 10／12；12／12 复现原 Python 文本 |
| native-mel-only | 只注入已捕获原生 Mel，保留 Python mask／count／encoder／decoder | 11／12 |
| native-encoded-only | 只注入已捕获原生 encoder 输出，保留 Python 预处理／prompt／decoder | 12／12 |

**只注入原生 Mel 已重现加噪桥梁样本的中文遗漏**，证明前端数值敏感性参与该条件的文本分叉。剩下的 clean 样本数字格式差异在注入 encoded 后重现。同一原生 Mel 上的 Python encoder 仍有数值差异，具体底层来源尚未判定。额外的“Python encoder 接收原生 Mel”只记录统计，没有保存该计算的额外原始数组；不声称可以仅凭文件重新计算这部分统计。
