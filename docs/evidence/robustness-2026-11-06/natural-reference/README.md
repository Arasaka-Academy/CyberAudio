# ASCEND 自然语音全量参考对照与音量因果实验

同一固定 Qwen3-ASR 模型的原生 Swift 与未修改 Python 参考，在完整 ASCEND 测试集上大部分输出一致；此前四个自然翻译、专名和空转写问题均在参考中原样出现。切换到参考实现没有显示整体准确率收益。单独将空转写样本的音量提高 12.04 dB 后，它仍为空；没有据此改变音频预处理、模型、默认参数或生产 App。

本阶段源码基线为 `main@8e2378b`；其[完整远程检查](https://github.com/Arasaka-Academy/CyberAudio/actions/runs/42320651628)通过 36 项原生契约、44 项工具测试、14 项原生渲染、全部行为回归和正式 App／Service／Assets 编译。该提交将检查和发布工作流固定到 Swift 6.3.3，消除安装动作将 `6.3` 当作 `6.3.0` 比较所产生的错误注记。CI 复用了预装 Apple Swift 6.3.3，并从新的空缓存键完成构建；没有声称它与上一轮安装的工具链发行字节相同。上游 action 的 Node 20 弃用 warning 仍存在。

## 固定数据与原生基线复验

沿用[完整自然基线](../natural-ascend/README.md)的原始 1,315 条测试录音、参考、元数据顺序及摘要，包含 685 条中文、257 条英文、373 条混说，来自两位说话人和四段会话。没有重采样、强制语言、参考文本提示、重试、跳过或筛选有利输出。

复用已验收原生 Helper，SHA 为 `efe377a791e01b88df04f32358015c5153b25e70172f29f84213723da8621659`；Native 源码、受校验 SDK 适配器、锁文件和打包资源与该构建一致。开始参考推理前，重新执行四个已知问题和六个按各语言首尾元数据选出的控制样本，**10／10 的文本、语言、时长、静音标记与模型身份全部复现**。这支持复用此前完整原生基线，并非又运行了一轮完整原生测试集。

首个外层脚本错误地比较整个 HTTP 响应，将耗时、内存和随机请求 ID 也算入相等条件，因而在原生复验成功后退出。该失败、原协议、脚本及结果原样保留；[资格核验](native-check-qualification.json)逐字段确认十条实质结果相同，新协议只修正驱动校验，复用已有十条结果，没有重跑原生推理，也没有删除失败记录。

参考调用原始 `mlx_audio.stt.utils.load_model(..., strict=True)` 和 `model.generate`，实际导入源码摘要及依赖版本见 [reference.json](reference.json)。设备为 Apple M1 Max／32GiB／macOS 27.0.1／arm64，[环境回执](environment.json)在本轮结束后读取。MLX 0.32.4、mlx-audio 0.6.4、Transformers 5.22.2、NumPy 2.3.4；GPU、greedy／temperature 0、auto language、空 system prompt、max 1024，完整参数在[冻结协议](protocol.json)中。没有替换模型方法或张量。

全部 1,315 次参考生成成功，零重试／跳过，参考进程运行 300.77 秒。它的计时范围与原生 HTTP 不同，不作为性能提升或麦克风端到端结论。所有模型工作顺序执行，最多一个所属推理进程，并使用禁止主动出站网络的沙箱。

## 四个自然问题均由参考原样复现

四条已公开署名示例的原文和两端输出见 [summary.json](summary.json)。它们都逐字相同：

- `所以我们现在开始talk about our research topics` 中的中文部分被输出为英文。
- `找个地方which is speak in english` 中的中文部分也被输出为英文。
- `Hong Kong` 被写成无关中文 `荒矿`。
- 0.6 秒、参考为 `thank you` 的录音，两端均输出空文本。

这确认了这些具体观察不只出现在当前 Swift 调用方中，但没有将全部误差归因于模型权重，也没有排除其他样本的数值敏感性；此前 Mel／encoder 边界实验和本轮 24 条规范化差异仍各自保留。两端一致不构成转写正确或人耳试听验收。

## 固定增益实验没有修复空输出

只读全量电平统计发现 169 条录音 RMS 不高于 -30 dBFS，其中 79 条不足一秒；直接扩大八倍会让其中 141 条削波，因此没有将它作为通用处理。

在完整参考结果出来后，另行冻结[七条录音的因果协议](level-plan.json)：包含已知空转写，以及从每种语言的低音量、四倍增益不溢出候选中按元数据首尾选择的六条控制。每条依次执行原始 PCM 和每个 Int16 样本精确乘四，共 **14 次**原生 HTTP 请求，均成功。增益为 12.0412 dB；没有改变时长、静音填充、采样率、提示或语言，也没有削波或增加抖动。

七个变换均与 FFmpeg `volume=4` 的 PCM 逐字节相同，七条原始结果全部复现冻结基线。空转写在增益后仍为空；七条总编辑数为 **16 → 16**，逐条编辑数无改善或回退，部分原始大小写／重复词发生变化。结果见 [level-summary.json](level-summary.json)。该 pilot 到此结束，没有扩大样本、搜索其他增益或采用自动增益策略。

服务的 `no_speech` 按既有契约仅表示精确数字静音，不能用模型空输出证明录音中无人说话；此次空输出仍为 `no_speech=false`。全局听写对空文本已有“未识别到语音”提示。没有将这个字段改为通用 VAD，也没有把字段语义修订当作质量修复。
