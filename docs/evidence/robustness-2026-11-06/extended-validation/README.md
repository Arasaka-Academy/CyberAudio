## 短句 TTS 的本机追加诊断

[150 次请求原始记录](m1-tts-probe-v3.json)、[汇总](tts-probe-summary.json) 和[采集源码](tts-probe-driver.py) 对应同一 M1 的独立实例：使用与 M4 失败周期相同的中文短句、`ono_anna`、PCM 流和未修改的实际 Helper。在 532.43 秒内 150 次请求均 completed，没有传输错误；后续同实例 Serena WAV、更新暂停／恢复、临时请求清理和 stdin EOF 正常退出通过，生产实例及隔离配置／Token 保持一致。该诊断在 12:58:58 UTC 结束，没有作为后台任务继续运行。

本次结论仅为“150 次内未复现终态失败”。同一句话的输出时长为 2.8–62.56 秒，中位数 4.16 秒，其中十次超过 15 秒；completed 只表示生成收到了结束标记，不能证明内容完整、没有重复或人耳可接受。

此前两个私有采集尝试也保留摘要和原始报告 SHA：第一版在 61 次成功后读取到 4,608,000 字节 PCM（96 秒）并触发 `IncompleteRead`，未能采集对应终态请求；第二版因将 HTTP 标头转成大小写敏感字典而在首个请求后断言失败。第三版修复了这两项采集问题，保留部分响应及完整请求记录。这些失败不被后来的 150 次成功覆盖；缺少终态错误码的第一次采集仍不能当作已证实的 `generation_limit`。
