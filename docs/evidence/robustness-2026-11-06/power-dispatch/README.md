# JIT／预编译 Power 对照与完整生成

2026-11-07 追加，正式基线 `2a19135`。只在独立 C++ 对象中把 float32 `Power` 从 JIT 库切到同一已打包 Metal 库；原 SDK、采样顺序、参数、模型和生产安装均保持原字节。它是因果诊断，未成为正式补丁。

## 标量控制

保持相同 Swift 公式和其余原生对象，两组标量探针均 exit 0。原 JIT 重现先前原生的全部 64 个逆频率；预编译 Power 则重现先前 Python 的全部 64 个值。索引／指数一致，幂输出 46 项不同，逆频率 42 项不同、最大绝对差 `2.9802322387695312e-08`，与[逐层定位](../layer-parity/README.md)吻合。

实际 Python `libmlx.dylib` 的选定函数反汇编显示直接调用 `Device::get_kernel`；原生 Swift 包使用 JIT 实现。私有补丁没有改变数学模式或 Metal 语言版本，尚未判定编译器内部哪一步产生舍入差异。

原生编译命令的 `MLX_VERSION` 标志为 `0.32.0`，保留头文件为 `0.32.4`。Swift 包标记、编译宏、头文件和 Python 运行时版本属于不同层，不能据此声称二者后端构建完全相同。具体源码／库／shader 摘要见 [dispatch-provenance.json](dispatch-provenance.json)。

失败样本的全段 RMS 约为 `0.0006801`／`0.0007249`（满量程归一化），这里只作信号描述，不把低电平、空 ASR 或 EOS 当成人耳结论。数值路径对齐没有解决短句内容缺失和过长生成，因此候选不采用，也不为它继续扩大矩阵或重跑严格长时验收。
