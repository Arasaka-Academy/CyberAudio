# 采样顺序定位与当前语言路由的配对诊断

正式 SDK、采样参数和 App 未修改。在 Apple M1 Max／32GiB 上，同一批前向数值已经完全一致的轨迹进一步显示：Swift 在 top-k 之后除以温度，Python 在之前执行；bfloat16 舍入可改变截断处的并列值。只调整该执行顺序的私有候选完成 144 个生成，均有 EOS，最长 11.04 秒；当前路由基线有一次无 EOS、最长 96 秒。全部输出回读后，候选有 5 对编辑数增加，已知失败样本仍有错词，因此未采用，也未启动新的两小时验收。

## 实际采样器对照

[采样计划](sampling-plan.json)固定复用前阶段五个样本、146 步的 logits 和历史。原生探针从当前受管理 SDK 提取原样的 `sampleToken`，仅增加最终 logits 观察点；2336 次采样全部重放原始 16 组 codec 向量。[原生过滤记录](native-filters.json)、[构建回执](native-build.json)和[运行回执](native-runner.json)保留源码摘要与结果。

Python 实际调用未修改的 `Model._sample_token`，只观察其最终 categorical 输入并继续调用原函数，直接／观察调用控制一致。这里真实导入的是 `mlx_audio.lm.sample_utils`，不是 `mlx_lm.sample_utils`；模型源码和实际采样模块 SHA 均记录于[逐项比较](sampling-comparison.json)。运行沿用隔离 MLX 0.32.4／mlx-audio 0.6.4 环境、相同种子与采样调用顺序，见[比较程序](compare-sampling.py)及[参考运行回执](reference-runner.json)。

| 项目 | 结果 |
|---|---|
| 全部最终分布 | 2336 项中 2078 项逐值一致；相同强制轨迹下 2328 个采样 token 相同 |
| 主生成器 | 146 个采样 token 全部相同；保留 EOS 的实现差异导致多数分布不完全相同，去掉该保护后的比较有 143／146 项精确一致，最大总变差约 8.84e-11 |
| 辅助生成器 | 2190 项中 136 项有限支持集不同，8 个采样 token 不同；最大总变差约 1.7087% |
| 已知失败轨迹 | 首个不同的辅助采样出现在零起始第 14 步、第 5 组：原生 1106，参考 988 |

Python 重复惩罚只看最近 64 个主 token，Swift 使用完整历史；此处每个轨迹最多 32 步，不能用该差异解释这批结果。比较是在强制原始历史上的条件分布，Python 采样结果没有自行构成完整生成轨迹，也不能据此报告真实失败率。

## 单变量候选与初步控制

[私有补丁](private-order.patch)只把温度除法移到 top-k 之前；参数仍为主／辅助温度 0.7、top-k 50、top-p 1.0、重复惩罚 1.05。完整文本预填充、EOS 保护、重复惩罚历史和模型权重保持原值。候选仅在私有路径编译，不替换共享 SDK／对象或正式 Helper，见[候选构建](order-build.json)。

[预先固定的六次生成](order-plan.json)包括已知失败、正常短句、两个英文数字、人名日期和失败重复。候选两次种子 196 的 token／PCM 完全相同，均为 7.2 秒；原失败前 15 个主 token 和前 12 个 codec 帧对应的 PCM 前缀一致。正常短句与日期控制的规范化回读保留原文；已知失败回读为“此句验证语音服务的稳定性和恢复能力。”，并非预期“持续验证…”。eric 的英文 `1234` 回读为 “You, toward side.”，dylan 为“一枪来三十四。”，均不能算内容通过。

全部五个原基线与六个候选输出经同一个最终 App Helper 完成 18 次 ASR，包括长音频分段和数字的强制英文诊断。原失败四段自动回读均为空；强制语言标签不证明实际发音。生成／回读分别约 25.64／18.86 秒，见[生成记录](order-generations.json)、[回读](order-asr.json)及[音频清单](order-asr-corpus.json)。

## 全部 144 对的当前路由对照

[矩阵计划](matrix-plan.json)沿用四文本 × 九音色 × 四种子（196、0、31、117），保留原始失败，不因 EOS 结果提前停止。128 个原基线 token／PCM 经摘要复核后复用；R11 前英文 eric／dylan 的 16 个旧基线不适用于当前路由，使用当前正式 SDK 重新生成。候选 144 次与这 16 个基线共 160 次新生成约 433.72 秒，均正常返回诊断报告；具体见[当前基线](current-baselines.json)、[候选矩阵](candidate-matrix.json)、[构建](matrix-build.json)和[运行器](matrix-runner.json)。

两组 288 个输出全部经相同最终 R12 Helper（SHA `46083a4f7ba269b7f28377bd9532ede44ac0a812a55a55d1e1f0a9bd225cf86d`）完成 294 次实际 HTTP ASR，约 160.38 秒、Helper exit 0。音频超过 24 秒时分段，所有 WAV 载荷均对照原始 PCM 切片核验。见[回读原值](matrix-asr.json)、[载荷清单](matrix-asr-corpus.json)、[汇总](matrix-summary.json)及[全部配对](matrix-paired-results.json)。

| 固定样本指标 | 当前路由基线 | 私有顺序候选 |
|---|---:|---:|
| 生成数 | 144 | 144 |
| 无 EOS | 1 | 0 |
| 超过 15 秒 | 2 | 0 |
| 中位／最长音频秒数 | 5.84／96 | 5.84／11.04 |
| 规范化精确回读 | 122 | 125 |
| 字母数字总编辑数 | 113 | 56 |

候选 10 对编辑数减少、129 对相同、5 对增加。具体回退包括 serena／0 的英文稳定性句漏掉 `the`，dylan／196 的 `Verify` 回读成 `Verified`，sohee／117 的 `Alice` 回读为 `Ellis`，以及 dylan／0 的 `Alice` 回读为 `Ali`。这些是回读变化，尚无人工听辨来分离 TTS 与 ASR 的责任。种子 196 的原失败虽从 96 秒变为 7.2 秒，仍有两个字符编辑，不能计作内容修复。

评分按既有 NFKC／casefold、去标点空格后的字母数字编辑距离，未做数字语义归一化。结果混合 TTS／ASR 误差，方言和数字写法也会影响统计；不能当作正式 CER／WER、总体失败率或音质评价。当前基线修正了 16 个语言路由条件，精确回读数也不能直接与旧路由阶段横比。候选保留待进一步定位，正式默认值未变，原 M4 严格两小时、固定语料／生命周期和试听门槛仍未接受。
