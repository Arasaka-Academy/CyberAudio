# 普通 Whisper large-v3-turbo 实测（2026-11-05）

**可以通过 Swift／Core ML 离线运行，但本次准确率未达到替换现有 Qwen 的条件。** 在 M4／16GiB、同一批 100 条公开真人录音上，普通 Turbo 比现有 Qwen 的 P95 延迟低约 20%，中英文错误率均更高。与 SenseVoice 相比，Turbo 英文更准确，中文错误率更高、识别更慢。结论限于本次固定语料和配置。

本次新增 WhisperKit 验证入口、独立资产锁、真实模型下载校验和两轮配对测试。生产 App／HTTP 后端继续使用原部署；本报告只评价 STT，不把前一轮 TTS 结果作为本次新测量。

本机和验收机均完成全部 29 文件的摘要校验。原生程序显式使用本地模型和 tokenizer、`download: false`，并在禁止网络的 sandbox 下运行。Mel 使用 CPU，编码器和解码器配置 CPU＋ANE。配置不能证明实际 ANE 使用，也不能证明能耗下降。

识别采用自动语言检测、`transcribe`、单 worker、无时间戳、temperature 0，允许 SDK 的最多 5 次温度回退；本次两轮均未触发回退。没有加入提示词、指定中文或根据参考文本修正输出。两轮 200 次语言检测全部匹配语料标签，100 条原始识别文本逐条完全一致。

语料复用 [固定 manifest](Results/2026-11-05/corpus.json) 和 [来源记录](Results/2026-11-05/provenance.json)：FLEURS test 前 50 条普通话和前 50 条美式英语真人录音，固定修订 `168de341b3db6859a9bac1c50a2ef5e3b47647e0`。总长 1010.48 秒，单条 4.32–19.12 秒。未按模型输出筛选；四组完整测试的 100 条 ID、参考文本、语言、录音 SHA256 均匹配。

顺序为：Turbo 首次加载和单条三次识别 → 新采集生产 Qwen 100 条 → SenseVoice 100 条 → Turbo 第一轮 100 条 → Turbo 第二轮 100 条。没有重叠执行推理请求；生产服务在原生测试期间保持驻留。

## 准确率和延迟

错误率越低越好。中文 CER、英文 WER 按总参考字符／词数汇总；Unicode 规范化后忽略大小写、标点，保留数字与原始文字形式，不转换简繁或日期／数字写法。P50／P95 使用 nearest-rank。

| 指标 | Qwen3-ASR 1.7B MLX | SenseVoiceSmall | Turbo 第一轮 | Turbo 第二轮 |
| --- | ---: | ---: | ---: | ---: |
| 中文 CER，50 条 | **7.9723%** | 8.7811% | 9.5898% | 9.5898% |
| 英文 WER，50 条 | **3.3457%** | 7.1561% | 4.7398% | 4.7398% |
| P50，100 条 | 796.21ms | 26.82ms | 659.06ms | 650.27ms |
| P95，100 条 | 1156.09ms | 84.12ms | 931.48ms | 923.41ms |
| 最慢请求 | 1382.41ms | 104.26ms | 1248.86ms | 1236.58ms |
| 识别调用累计耗时 | 82.71s | 3.28s | 69.09s | 68.49s |

Turbo 比 Qwen 的中文 CER 高 **1.6176 个百分点**、英文 WER 高 **1.3941 个百分点**。两轮均满足 STT P95 ≤3 秒，但原生 `compare` 均返回 `accuracyNonRegressing: false`。

延迟包括各自文件解码：Qwen 使用服务端 `processing_ms`，包含 FFmpeg；原生使用文件识别调用的墙钟时间，包含 SDK 音频读取、自动语言检测和推理。模型加载、资产摘要校验不包含在请求延迟内。HTTP 额外时间保存在逐条基线中。SDK 的编码／解码分项为辅助诊断值，不作为可相加的请求墙钟时间。

固定参考文本包含括注、专名和数字写法差异，会影响绝对错误率。例如 `zh-041-1914` 的“二十世纪”被 Turbo 写成“20世纪”，同时“基因变异”“隐性”还出现了实际识别差异；`en-010-1776` 的 `Dunlap broadsides` 被写成 `Den Lap broadsides`。这些例子解释误差来源，不能替代独立的实体标注。三种模型按同一规则评分，没有为任一模型修改参考文本。

## 加载与内存

| Turbo 测量 | 加载／编译／预热 | 资产校验另计 | 进程 peak RSS |
| --- | ---: | ---: | ---: |
| 本次首次加载，单条重复三次 | 70.29s | 645.51ms | 1,813,004,288 字节，约 1.69GiB |
| 有编译缓存，完整第一轮 | 1.27s | 721.21ms | 1,667,170,304 字节，约 1.55GiB |
| 有编译缓存，完整第二轮 | 1.02s | 681.65ms | 1,859,158,016 字节，约 1.73GiB |

首次加载含 Core ML 编译、预热、模型和 tokenizer 加载，指本实验首次使用该模型，未执行机器冷启动或清空系统缓存。首条录音在加载后连续三次耗时 687.27／623.81／626.78ms，识别文本一致。有缓存时也需加上单独记录的资产校验时间，不能把 1.02 秒直接当作完整应用启动时间。

SenseVoice 本轮进程 peak RSS 为 1,013,596,160 字节，加载为 88.36 秒；它与前一轮不同二进制的缓存加载记录分开保留，不混用。Qwen 的响应包含常驻生产进程的历史 peak RSS／Metal 内存，统计范围与新建原生进程不同，因此本次不据此判断系统总内存降低。

目标机测试前后已有约 7.46／7.45GB 的 swap 使用，生产服务及其他应用仍驻留。本报告反映该运行环境下的结果，不等同于重启后只运行单模型的硬件极限。未取得 Instruments 的实际 ANE 轨迹或每请求能耗测量，不能声称更省电。

## 结论边界与复核

普通 Turbo 的原生离线推理、两轮一致性和本次延迟要求已验证。中英文准确率均未达到现有“不退步”条件；本语料仍缺专门的中英混说和人工数字／专名标签。生产 Helper／HTTP 服务迁移、流式／长音频／取消和原生生命周期回归不在本次已通过范围内。

测试结束于 2026-11-05 10:29 UTC 的生产检查确认：原实例未重启，`ready`、`busy=false`，仍使用 Qwen3-ASR 1.7B。本次没有修改生产配置或切换模型。

小型脱敏逐条结果、两轮原生比较输出、环境、版本和摘要见 [实测证据](Results/2026-11-05-whisper-turbo/README.md)。保留的数据已重新核对全部音频摘要及参考文本，并可离线重算比较。准备工具使用开发机 Python；Whisper 推理本身使用原生 Swift／Core ML。

本次 Release 构建通过，41 项 Python 测试及原生证据工具 11 项行为场景通过，shell 语法和 Python 编译检查通过。CLT 链接搜索路径警告与一条上游 Starlette 弃用警告仍存在。没有将工具测试通过等同于生产迁移通过。
