# Core ML 迁移验证记录（2026-11-05）

**本轮不切换生产后端。** 真实模型已能通过 Swift／Core ML 离线推理，但 SenseVoiceSmall 在同一组 100 条真实录音上的中英文准确率均有退步，不满足用户约定的替换门槛。现有 MLX／Python 部署继续使用；生产 Swift Helper、HTTP 服务和原生生命周期回归尚未实施。

本轮实现了独立原生验证程序、固定资产下载与校验、公开语料准备、生产基线采集、逐条配对比较、TTS 逐步音频记录和最终验收检查。开发验收脚本使用 Python，原生模型推理程序不依赖 Python／MLX。

SenseVoice 预处理固定 CPU FP32，编码器 FP16、CPU＋ANE；识别采用自动语言、模型自身的 with-itn（embedding 14）数字／日期格式化。TTS 使用 1.7B CustomVoice，embedding CPU，解码器 CPU＋ANE，单 worker、不分句并发、seed 42、1200 tokens 上限。完整命令见 [README](README.md)。

最后的 Release 构建使用未修改的 SDK 固定提交。因网络下载超时，官方 Nemo 二进制归档先单独下载并通过上游 SHA256 校验，再写入本任务的 SwiftPM 缓存；SDK 源码没有为最终构建打补丁。Git 镜像指向相同的官方固定提交，本机缓存路径不属于交付依赖。CLT 链接阶段仍有上游框架搜索路径警告，不能称为无警告构建。

## 公开真实语料及准确率

用户没有现成录音集，因此固定选取 FLEURS test 的前 50 条普通话和前 50 条美式英语真人录音，未按模型结果筛选。共 100 个不同 ID、100 个不同音频 SHA256，约 1010.48 秒，总音频 64,676,520 字节，最长 19.12 秒。

来源为 `google/fleurs@168de341b3db6859a9bac1c50a2ef5e3b47647e0`。完整中文／英文 Parquet 源文件分别通过官方 LFS SHA256 校验，重新提取后，100 条音频摘要及参考文本与本轮实测输入全部一致。FLEURS 的 prompt ID 可重复，样本 ID 使用固定行号消歧，避免覆盖不同说话人的录音。

| 指标 | 现有 Qwen3-ASR 1.7B MLX | SenseVoiceSmall Core ML | 结果 |
| --- | ---: | ---: | --- |
| 中文 CER（50 条） | 7.9723% | 8.7811% | 退步 0.8088 个百分点 |
| 英文 WER（50 条） | 3.3457% | 7.1561% | 退步 3.8104 个百分点 |
| STT P95（100 条） | 1173.88ms | 83.18ms | 达到 ≤3000ms 的延迟要求 |

按参考字符／词总数汇总错误数，使用 Unicode 规范化，忽略大小写和标点、保留数字。中英文分别使用 CER／WER 判断准确率。两个引擎使用相同 WAV、相同参考文本和自动语言策略，比较程序检查 ID、重复序号、音频摘要、参考文本与语言标签，并拒绝不完整报告。

延迟口径：基线为服务端 `processing_ms`，含 FFmpeg 解码；原生为 `transcribe(audioURL:)`，含 SDK 解码，均不含模型冷加载和文件摘要检查。基线 HTTP 总时延另存。主要基线在 Core ML 首次编译结束后重新独立采集，随后再运行原生 100 条请求；早期与编译重叠的基线不用于表格。

M4 的 SenseVoice 首次加载／编译为 93.57 秒，已编译缓存下加载为 107.13ms。M4 100 条进程 peak RSS 为 732,774,400 字节。RSS、MLX Metal 活跃内存及系统／ANE 占用的统计口径不同，本轮没有据此判断系统总内存是否降低。

本语料没有专门的混说覆盖，也没有人工数字／专名正确率标签，这两项仍缺失。部分参考文本包含外文专名、括注和数字，因此 CER／WER 同时受到参考文本与口语呈现方式影响。两引擎在同一规则下仍出现明确退步，结论仅适用于本次固定的 100 条公开语料，不外推成所有实际业务录音的排名。

## TTS

M4 的最终配置采用 speech decoder `throughput` 和 multi-code decoder `fused`，两者均使用锁定模型现有的函数，没有另换模型或修改 SDK。`throughput` 约每 320ms 音频回调一次；单 worker、无分句并发，仍为渐进输出。测试文本为“今天下午三点十五分，请提醒我开会。”，指令为“请用自然、轻快的语气说话。”。

同一实例中九音色各连续生成两次，18 次全部报告 EOS，回调拼接 PCM 与最终结果逐字节相等。每次有 9–24 块，音频 2.64–7.60 秒。以下 RTF 包含真实生成及回调时间，不含加载和资产摘要检查；首包时间从调用生成开始计时。

| --- | ---: | ---: | ---: | ---: |
| serena | 3066 | 0.9990 | 0.7389 | 1076.8／263.7 |
| vivian | 3065 | 0.9282 | 0.7413 | 920.6／267.2 |
| uncle_fu | 3010 | 0.8937 | 0.7423 | 939.3／280.2 |

独立的 Serena 三次复测为 RTF **1.0008／0.7452／0.7368**，首次首包 1106.3ms。最终门槛保守取相同配置下全部 24 次 EOS 完整生成的最高 RTF，包含九音色、三次复测、取消后的恢复请求及英语两次，不计有意取消的半句。因此 `ttsRealTimeFactor = 1.0007914`，尚不能确认稳定满足严格的 RTF <1。九音色单轮都低于 1，不能消除其他重复测量中已出现的超限。

取消测试在第一句两块音频（0.64 秒音频）后停止，状态为 `cancelled`；同一 TTS 实例下一句正常到达 EOS，3.92 秒音频、RTF 0.7378，两次回调 PCM 均与返回音频相等。独立的 Ryan 英语文本配合英语表达指令，两次均到达 EOS，RTF 0.9161／0.7294，首包 873.2／259.3ms。

首次使用 fused 函数的加载／编译为 60.98 秒；随后九音色实例加载为 1.59 秒、peak RSS 1,686,306,816 字节。编译缓存已经建立，1.59 秒不能当作首次安装的启动耗时，也不能据此推断系统总内存或能耗下降。

音色映射明确处理 `uncle_fu → uncle-fu`、`ono_anna → ono-anna`。TTSKit 对未知字符串会回退到 Ryan，原生程序先验证 `Qwen3Speaker` 枚举再调用生成，报告包含实际 SDK 名称和 token。早期未映射这两个名称的辅助结果不用于九音色验收。

每次生成保存 24kHz 单声道 PCM16 WAV，以及真实逐步回调拼接的 PCM。SDK 会在 EOS、token 上限、音频比例上限或 KV 上限时正常返回；本工具通过固定 SDK 的同步日志回调记录停止原因，只有 EOS 才标记 `completed`，取消／超时优先使用自己的状态。字节相等只说明回调没有丢失返回结果，不证明句子发音、语义和表达完整。

M1 Max 辅助复测确认了这一差别：Serena 在 104 步／8.32 秒音频后命中 `Audio token ratio limit (104/104 steps)`，RTF 2.4777，状态为 `generation_limit`、`eos_verified: false`。因此早期 M1 Max 九音色等长输出不能作为完整生成的通过证据；该现象的原因尚未确定，不影响 M4 的独立 EOS 记录。

人工音色／表达指令试听与实际连续播放尚未验收，机器生成成功和字节相等不能替代这些检查。

## 能耗、计算单元和生产切换

本轮确认了配置使用 `.cpuAndNeuralEngine`，并在禁止出站网络的 sandbox 下运行真实 STT／TTS。没有采集 Instruments 的实际 ANE 计算轨迹，也没有取得重复测量的每请求能耗下降证据。报告中的 `ane_trace_verified` 保持 `false`。

目标机没有完整 Xcode／`xctrace`，`sudo -n` 不能获得采样权限；本机完整 Xcode 的许可尚未接受，本轮未代用户接受许可、安装 Xcode 或更改 sudo 配置。能耗与实际 ANE 执行仍是后续验证条件。

准确率门槛已失败，本轮按方案保留原部署。未变更 App 启动配置、模型目录、HTTP 路由、认证、单任务互斥、更新排空、断连处理、退出或重启逻辑；原生服务层尚无回归结果。未来候选模型先满足准确率和能效门槛，再进入 Helper／HTTP 迁移。

最终原生 `gate` 使用实测输入返回 `accepted: false`，退出码 2。缺失／失败项为 `mixed_speech`、`accuracy`、`entities`、`tts_rtf`、`listening`、`energy`、`ane_trace`、`api_lifecycle`。其中 `entities`、试听、混说、能耗、ANE 跟踪和原生 API 回归没有被误填为实测失败或实测通过；布尔值 false 表示尚未取得通过证据。2026-11-05 09:44 UTC 复查生产 `/ready`，仍为原实例、ready、busy=false，当前模型仍是 Qwen3-ASR 1.7B。
